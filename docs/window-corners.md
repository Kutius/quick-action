# 窗口圆角与卡片形状

面板是一个无边框的常驻窗口（`Frameless` + `Panel`）。它的外轮廓并不完全由卡片自己的 `Radius` 决定：Windows 会先把窗口裁成系统自己的圆角，卡片只能画在这条裁剪线以内。本文记录这个约束、现在的做法，以及想画别的形状时的取舍。

## 现象

把卡片画成 24 DIP 的胶囊后，窗口实际仍是小圆角；卡片圆角之外的四角露出深色背景，在深色主题下接近黑色。

## 原因

Windows 11 的 DWM 会给无边框窗口套上系统自己的圆角，半径固定（实测 125% 缩放时约 10 物理像素，即 8 DIP），并把窗口内容裁剪到这条弧线。MyGo v0.8.3 的 `WindowOptions.CornerRadius` 在各平台的行为不同：

- macOS：真正把内容和材质裁到给定半径；
- Windows：只调用 `DwmSetWindowAttribute(DWMWA_WINDOW_CORNER_PREFERENCE, DWMWCP_ROUND)`，请求 DWM 圆角，圆角大小由系统决定，传入的数值被忽略；
- Linux：不做圆角。

所以窗口的真实轮廓始终是系统半径的圆角矩形。卡片画 24 DIP 胶囊时，胶囊弧线缩在窗口内部，两者之间的楔形区域露出原生 UI 的根背景——主题的 `Background`（深色 `#18181b`），看起来就是黑角。

## 现在的做法

1. 卡片半径跟随窗口：`cardRadius = 8`（`widget.go`）。内部可交互区域也用 8，保持同一套几何。
2. 在卡片下面铺一层相同的材质渐变（`view` 里的外层 `Box`）。DWM 的裁剪线和卡片弧线即使差半个像素，露出来的也是卡片的面，而不是背景。

这样窗口的裁剪线就是卡片的边线，系统的窗口阴影、贴边吸附和点击区域都不受影响。

## 替代方案与取舍

### 透明窗口 + 自绘阴影

窗口放大，四周留透明边，卡片按任意圆角绘制，阴影自己画，并用 `DisableShadow` 去掉系统阴影。

- 透明边仍然属于窗口的命中区域：卡片周围一圈会吞掉对桌面和其他窗口的点击。
- 失去 DWM 的窗口阴影和外框，阴影要自己画，还要跟随主题和 DPI。
- 贴边吸附按窗口矩形计算，需要把透明边的宽度补进去，否则贴不到屏幕边。
- 原生 UI 的透明依赖 DirectComposition（`Transparent` + 原生 `Content`）；Windows 10 或没有合成的环境会退化成不透明背景。
- 要消除第一点，需要在 `WM_NCHITTEST` 里对透明边返回 `HTTRANSPARENT`，MyGo 没有暴露这个钩子。

对常驻的小面板来说，这些复杂度和交互代价不划算。

### SetWindowRgn

用 `SetWindowRgn` 把窗口裁成胶囊，同时把 DWM 的圆角偏好关掉（`DWMWCP_DONOTROUND`），否则系统的小圆角会先切掉胶囊的两端。

- 需要直接调用 Win32，MyGo 没有封装。
- DWM 的阴影跟随窗口边框，不一定跟随 region，形状和阴影可能对不上。
- DPI 或尺寸变化时要重算 region。
- 仍是平台特定的 hack，不是原生外观。

### 接受原生圆角（现在的选择）

窗口是什么形状，卡片就画什么形状。外观与 Windows 11 自己的菜单、浮层一致，阴影、吸附、命中测试都保持原生。

如果以后确实需要非矩形轮廓（胶囊、圆形等），优先考虑 MyGo 的 flyout：它本来就是透明窗口，由 MyGo 管理，适合弹出层；常驻窗口不建议做成异形。

## 验证

125% 缩放下，200×48 DIP 的窗口是 250×60 物理像素，DWM 的圆角弧线约 10 物理像素。截图放大后，卡片发丝边与裁剪线重合，四角没有背景色露出。
